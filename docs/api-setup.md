# YouTubeの取得と配信
GitHubのSettings → Secrets and variables → ActionsでリポジトリSecret `YOUTUBE_API_KEY` を登録します。YouTube Data API v3を有効にしたキーを使います。Twitchの設定は不要です。

Actionsの **Collect broadcast snapshot** で手動取得できます。取得・所属監査・ビルド・テストを通った静的ファイルが `portal-dist` 成果物にまとまります。キーは取得ステップだけで参照します。正常取得で表示対象が0件の場合も通常の成果物を生成します。表示対象がある場合は追加で単一HTMLのプレビューを生成します。

無料GitHub Pagesで公開するときは、最終承認後にリポジトリをPublicにし、Settings → PagesでGitHub Actionsを選択し、Actionsのリポジトリ変数 `PUBLISH_PAGES` を `true` にしてmainから手動取得します。定期取得に成功すると配備が更新されます。変数が未設定の間は配備を実行しません。

## 取得の頻度と予算
JSTの0〜16時台は毎時7分、17〜23時台は各時7・17・27・37・47・57分の計59回を予定します。実行時刻はGitHub側で遅れることがあります。最近の投稿20本と既知の動画IDを再確認します。ライブの同時視聴者数は同じvideos.list応答から読み、非公開・欠落は不明として扱います。

検索はPT日単位で最大80リクエストです。チャンネル・状態別に検索済みを記録し、翌日は開始チャンネルを回します。毎回59チャンネルを新規検索するスケジュールではありません。アップロード先プレイリストIDはチャンネルIDとPT日をキーに再利用します。59チャンネルの候補がそれぞれ50本以内の場合、通常APIは約7,021単位/日（59件×2取得×59回＋ID調査約59回）。動画候補の追加バッチ、失敗再試行、追加実行で増えます。

通常APIのローカル打ち切りは8,000、検索は80（標準枠10,000および別枠100回）。集計はActionsキャッシュに依存します。キャッシュ消失や、同一Google Cloudプロジェクトを利用する他の処理があれば、プロジェクト全体の消費は異なります。取得制限・未取得は以前の有効期限付きデータとエラー／部分取得状態を保持します。
