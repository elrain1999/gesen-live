# YouTubeの取得と配信
GitHubのSettings → Secrets and variables → ActionsでリポジトリSecret `YOUTUBE_API_KEY` を登録します。YouTube Data API v3を有効にしたキーを使います。Twitchの設定は不要です。

Actionsの **Collect broadcast snapshot** で手動取得できます。取得・所属監査・ビルド・テストを通った静的ファイルが `portal-dist` 成果物にまとまります。キーは取得ステップだけで参照します。正常取得で表示対象が0件の場合も通常の成果物を生成します。表示対象がある場合は追加で単一HTMLのプレビューを生成します。

無料GitHub Pagesで公開するときは、最終承認後にリポジトリをPublicにし、Settings → PagesでGitHub Actionsを選択し、Actionsのリポジトリ変数 `PUBLISH_PAGES` を `true` にしてmainから手動取得します。定期取得に成功すると配備が更新されます。変数が未設定の間は配備を実行しません。

## 取得の頻度と予算
JSTの0〜16時台は毎時17分、17〜23時台は毎時07・22・37・52分の計45枠です。Workerは昼間毎時47分、夜間毎時04・19・34・49分に鮮度を確認し、必要なら同じActionsを起動します。毎時32分のGitHub予備枠は成功から昼間60分・夜間15分経過した場合に起動します。実行はリポジトリ全体で直列化します。近接した自動起動は昼間50分・夜間12分以内の直近試行を再利用またはスキップします。

検索は昼間1回・夜間2回／更新、通常計画は17×1＋28×2＝73回／PT日です。429再試行もこの枠を使います。既知動画の継続確認はvideos.list、最近20本の発見はplaylistItems.listを維持し、検索は未確認チャンネルのライブを優先、次に新規予定を調べます。複数同時配信、59チャンネル、アーカイブ保持数は変更しません。

検索前にGITHUB_TOKENのContents writeで専用ブランチ `youtube-quota-state` の `search-budget.json` へ最大1/2回を予約します。Contents APIのSHA更新で競合を検出し、同じ15分枠のWorker・schedule・手動・pushは重複予約しません。`America/Los_Angeles` の日付で80回まで予約し、未使用予約・途中失敗・応答消失も返却しません。予約不能なら検索0回で通常APIを継続します。初回または台帳消失時は当日の既使用量が不明なため80回使用済みで初期化し、翌PT日に再開します。キャッシュ消失では予約枠は復活しません。予約日の翌日に開始・再試行した検索も停止します。

通常APIのローカル打ち切りは8,000で、既存のActionsキャッシュ依存です。検索枠の共有保証はこの台帳を経由する取得に限ります。同じGoogle Cloudプロジェクトの外部利用・旧版の直接起動には適用できません。実API検索は予約環境変数がない場合に停止します。予約数は実呼出数の上界であり、実測値はAPI telemetryとCloud Consoleを併用してください。

キャッシュ復元後に公開JSONと生成・成功時刻を比較し、新しいデータを採用します。公開直前にも比較し、古い生成・成功時刻の公開を拒否します。公開JSONを確認できない場合は処理を止め、現行Pagesを保持します。API制限時の部分データは公開可能なまま、公開後の `acquisition_status` ジョブで取得失敗・延期・台帳障害を失敗表示します。通常の計画的検索上限は失敗扱いにしません。
